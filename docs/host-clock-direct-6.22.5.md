# 6.25.8 implementation and evidence

Starting source: Render export 6.22.4; live health during investigation confirmed 6.22.4-graphics1 / protocol 85. New export 6.25.8-clock1 / protocol 86. No SQL migration or new dependency; connection policy is in the existing room config JSON.

Reproduction before patch: two independent production VM clients, real local WS relay, mocked fast reliable DIRECT, outgoing WS control delayed 120 ms, actual performance-clock frame scheduling. After 2.2 seconds the host was ahead by 19–20 ticks; the test failed its <=3-tick tolerance. Startup previously waited 100 ms on host and 100 minus peer RTT/2 after START arrival on guest, even though START itself travels through WS. This can produce the reported role asymmetry; it is not proof no other device-specific cause exists.

Correction: host measures current init/ACK control RTT, chooses a bounded future start deadline and sends RTT/remaining wait; guest compensates using this control RTT instead of DIRECT peer RTT. Duplicate ACK sends remaining time rather than restarting a full countdown. Checkpoint handling retains the prior race fix.

Clock pacing: ping probes remember local tick and epoch; peer pong includes epoch/tick. For matching epochs the local midpoint tick minus peer tick estimates skew, smoothed at .5; samples beyond 120 ticks are rejected. A client estimated >2 ticks ahead consumes at most one tick of wall-clock budget per RAF without advancing the simulation, allowing the other to catch up. Both roles use the same rule. No input packet/button is discarded and no world state is force-shifted. Epoch initialization resets timing samples. This assumes roughly symmetric network paths; strongly asymmetric queueing may bias the estimate. On persistently slow devices the faster peer may temporarily slow; this cannot make an overloaded device sustain 120 Hz.

DIRECT-only policy: host selects auto/direct before room creation, stored in room config and inherited by guest. Guest cannot override via join payload. DIRECT-only forbids rb-input/rb-hash and legacy game input/state relay; client also prevents their WS routing. WS remains necessary for auth/lobby/ICE, hello and checkpoint/init/ACK/START/resync control, not normal gameplay input. If direct ICE times out or direct closes, clients fail explicitly / pause instead of selecting WS. No auto-detection of Wi-Fi SSID. Auto mode retains prior direct preference/background retries/WS fallback. A backend missing connection-policy support is caught before entering a requested DIRECT room, and the mismatched room is closed.

Evidence after patch: representative delayed-control test ended with tick gap 0. Tests intentionally advanced host and guest separately by 9 ticks; each leading side applied clock holds, returned within <=3 ticks and kept shared confirmed-state hashes without epoch reset. DIRECT-only unavailable/success/loss cases have zero WS gameplay packets; relay rejects injected WS input; a join cannot downgrade the policy. A DIRECT-only coordinator disconnect also pauses without spawning a WS repair epoch. Existing graphics, 25 fighter pairings, native renderer, interpolation, rollback, repair, prior ACK/START and fallback tests pass.

Full npm test: Node 24.22.1; 152 passed, 0 failed/skipped/cancelled. Log: validation-6.25.8.txt. Native WebRTC is mocked; real physical browser/device Wi-Fi behavior and subjective smoothness remain unverified. No claim of zero lag, universal DIRECT reachability, or removal of all host/guest disparities on arbitrary hardware.
