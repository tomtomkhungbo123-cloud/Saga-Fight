# 6.22.2 — compact measured peer ping and preferred DIRECT

Production changes: online.js, style.css, build stamps in game/core/index, protocol 84 in client/relay, server health build 6.22.2-direct1. Requires both players to reload the same new build. Patch applies over 6.22 or 6.22.1, retaining the ACK/START recovery fix.

Badge now renders only the actual peer RTT plus a CSS color dot. Server RTT and role/transport/debug text remain in tooltip/metrics. Thresholds: good <=80 ms/jitter <=40 ms, fair <=150 ms/jitter <=80 ms, bad above these or suspended; pending uses em dash and gray. Explicit hidden styling keeps the flex badge invisible outside an online room. Numeric label and aria-label accompany the color.

DIRECT preference: eight-second initial attempt using host ICE candidates and no STUN/TURN. WS remains the fallback. While running on WS, the host may negotiate DIRECT in the background after 15 seconds, then 30 seconds between failures, capped at three additional attempts. No gameplay pause or checkpoint on background failure. Both local/remote DataChannel probes and host selection/guest ACK are still required before switching, then one checkpoint recovery. Failed background negotiation tells the peer to release its pending connection without echoing FALLBACK indefinitely.

Each SDP/candidate/ready/fallback signal carries a negotiation generation. Stale signals are ignored. Up to 64 early candidates for the next generation are retained even if they arrive before the offer. New offers replace old pending guest negotiation. No Wi-Fi SSID detection or inference from public IP is used; a verified reachable DIRECT channel is the criterion. Client isolation, VPN/firewall and browser policies may prevent local direct connectivity.

Verification: 128 full-suite tests pass (Node 24.22.1), plus focused three-test rerun after explicit hidden styling. New tests verify measured RTT text and thresholds without substituting server ping; WS-to-DIRECT background upgrade with exactly one epoch/checkpoint; failed background attempt leaves WS gameplay unblocked with unchanged epoch; connected mocked peers received candidates. Existing latency/dropped START, checksum repair and WS reconnect regressions pass. Tests use independent VM clients and real local WS with mocked WebRTC. Native browser/Wi-Fi device connectivity and mobile FPS are not verified.
